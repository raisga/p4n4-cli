**p4n4 0.3.0** adds System 1: fast typed decisions with laya, off by default, with evaluation gates, calibration, labelling and drift alerts.

```bash
pipx install p4n4==0.3.0    # or: pip install p4n4==0.3.0 (Python 3.11+)
```

> **Trusted networks only.** p4n4 0.3.x is meant for development and trusted local networks. Don't expose its service ports to the internet or to networks you don't control.

## Highlights

- **`p4n4 ai system1 enable`:** adds the `system1` profile to the ai layer, generates `SYSTEM1_API_KEY`, copies the default question sets, writes n8n's credentials, pulls the pinned checkpoint and waits for the service. `disable [--purge]`, `pull` and `status` manage it. `status` names the checkpoint's repository when `SYSTEM1_REPO` serves a fine-tuned one, and flags sets the service loaded before their files changed.
- **Decisions and evaluation:** `decide <set> --state FILE|-` asks one question set. `eval [<set>]` checks every set against its gates, per language when there are several, and exits 5 when one fails. `--fit-thresholds` and `--fit-calibration` propose thresholds and per-question temperatures, and `--save-calibration` writes the site calibration and sets `SYSTEM1_CALIBRATION`. Both talk to the service through `docker compose exec`, so no host port is needed.
- **Feedback and labels:** `feedback <set> [--append]` turns the confirmations Node-RED kept into evaluation lines. `label <set> --input FILE [--write]` labels past events in batch and writes them to `ai_events` for Grafana's annotations.
- **Wired into the stacks:** `init` and `enable` give the iot layer the same `SYSTEM1_API_KEY` for Node-RED's `p4n4-system1` subflow, and generate `OPERATOR_INTAKE_TOKEN` and `SYSTEM1_ALERT_TOKEN` with n8n's `p4n4 Operator Intake` and `p4n4 System 1 Alerts` credentials, for Grafana's drift alerts.
- **`p4n4 secret rotate`** rotates the System 1 keys and keeps the n8n credentials in step.

## Fixes

- `p4n4 secret rotate` changes only the rotated keys in each `.env` and keeps its comments and layout.
- `p4n4 ai system1 enable` creates `config/system1/calibration` before the service mounts it, so Docker doesn't create it as root. When `eval --save-calibration` can't write there, it says so instead of failing with a traceback.

## Compatibility

- Requires **p4n4-lib 0.3.0** (installed with it).
- System 1 runs `ghcr.io/raisga/p4n4-system1:0.1.0`, which the p4n4-ai stack pins (`SYSTEM1_IMAGE`).
- Projects scaffolded by 0.3.0 pin **p4n4-dashboard 1.2.0** (`--layer dashboard`), which pairs with **p4n4-api 0.2.0**.

## Upgrading from 0.2.x

- Projects scaffolded before 0.3.0 don't have the stacks' System 1 files (the ai layer's `system1` service and question sets, Node-RED's subflow, Grafana's drift alerts). Scaffold a new project, or copy them from the current p4n4-ai and p4n4-iot, then run `p4n4 ai system1 enable`, which generates the missing keys and credentials.
