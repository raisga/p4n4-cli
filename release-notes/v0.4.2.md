**p4n4 0.4.2** prepares new projects for the ai layer's incident investigator (p4n4-ai's `agent` profile).

```bash
pipx install p4n4==0.4.2    # or: pip install p4n4==0.4.2 (Python 3.11+)
```

> **Trusted networks only.** p4n4 0.4.x is meant for development and trusted local networks. Don't expose its service ports to the internet or to networks you don't control.

## Highlights

- **`AGENT_API_TOKEN` from the start:** `p4n4 init` generates the bearer token of the incident investigator's status API (p4n4-ai's `agent` profile) in the ai layer's `.env`, so adding `agent` to `COMPOSE_PROFILES` later needs no new secret.
- **Rotated and checked:** `p4n4 secret rotate` gives `AGENT_API_TOKEN` a new value, and `p4n4 validate` reports it and `AGENT_MODEL` missing while the `agent` profile is enabled (p4n4-lib 0.4.2).

## Compatibility

- Requires **p4n4-lib 0.4.2** (installed with it).
- `p4n4 init` takes the dashboard layer from p4n4-dashboard's `main`, which pins **p4n4-dashboard 1.5.0**; it pairs with **p4n4-api 0.4.0**.
- The `agent` profile runs `ghcr.io/raisga/p4n4-agent:0.1.0`, from p4n4-ai's `main`.

## Upgrading from 0.4.1

- Nothing to change. To run the investigator in a project created before 0.4.2:
  - take the `agent` service from p4n4-ai's `docker-compose.yml` on `main`, if the ai layer's has none;
  - add `AGENT_API_TOKEN` (any long random value, e.g. from `p4n4 secret generate`) and `AGENT_MODEL` to the ai layer's `.env`, and `agent` to its `COMPOSE_PROFILES`.
